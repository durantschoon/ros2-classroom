# Executor worktrees start at a stale commit

## What happened

5 of 5 reported launches here: the isolated worktree was created at an old commit of the
default branch, not at the branch holding the prompt. Known upstream (README:
'wrong bases twice'; commit 6ff6b54) but only in repo READMEs, not in the
skill's prompt template.

## Suggested direction

Put a 'first step: verify the prompt file exists, else fast-forward to the
named base' block in the skill's prompt template so every new repo gets it.
