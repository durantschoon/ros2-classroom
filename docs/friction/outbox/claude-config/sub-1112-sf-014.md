# Many LLM authors, single-writer operations: the system has no shape for either

## What happened

log-friction's capture ends in AskUserQuestion and its blurt column is 'the
human's words', so an LLM author cannot submit. Rows carry no author, source
repo, machine or evidence. One shared CSV conflicts under concurrent appends.
Lessons about repo A arise in repo B. Nothing names single-writer operations
(curating, reserving a stage number, merging, releasing, redact-process's
force-push, make claude-publish) and nothing stops two machines doing one at
once; a human gate can be approved on two machines. This session nearly patched
SKILL.md from a second machine while claude-config's own pipeline was live.

## Suggested direction

Needs a design session. Sketch: a file-per-submission inbox with provenance and
occurrence counts (no conflicts by construction); an outbox in the contributing
repo when the target is unreachable; a triage mode that folds inbox into the
CSV, dedupes by bumping occurrences, applies the design gate, and leaves
buckets to the human; claim files for single-writer roles, using git push as
the compare-and-swap, with expiry; a roles list per repo; a machine roster
written at apply time. Cheap first step: 'commit AND PUSH the prompt before
launch' makes stage-number reservation a real compare-and-swap.
