# Stage 02 — Tests before ports: pin the scripts' behaviour

Branch name for this stage: `stage-02-tests-before-ports`. Base: `python-port`.

Read `docs/stages/README.md` first. Its gates, environment facts, and
guardrails apply to this stage and are not repeated here.

## Motivation (measured)

Stages 03–05 port every script to Python, and guardrail 8 says behaviour is
preserved exactly. Today nothing could tell us whether it was:

1. **Six host scripts have no tests at all**: `compose-command`, `compose-up`,
   `check-host`, `run-quiet`, `open-url`, `base-image-digest`. `make selftest`
   exercises some of them incidentally, on one platform, down one path. The
   WSL, macOS, docker, and failure paths have never run under test. Two of
   these scripts exist *because* of bugs found by hand (`open-url`: a browser
   command opened a text editor on WSL; `compose-up`: Podman silently kept a
   stale image), and neither fix is pinned by a test.
2. **Container scripts are partly covered.** The suite covers `pkg` and
   `install-ros-packages`, but never runs `tutorial`, never checks that
   `init-workspace` is idempotent, and never checks that `pkg new` refuses to
   clobber an existing package, which guardrail 7 asserts.
3. `make selftest` takes about ten minutes, which is too slow to be the only
   oracle while porting six small scripts.

This stage changes no script. It adds tests that pass against the current shell
implementations, so that stages 03 and 04 can prove their ports equivalent.

## The change

### 1. Black-box tests for the host scripts: `tests/host/`

Python `unittest`, stdlib only, Python 3.9-compatible, one module per script
(`test_compose_command.py`, and so on). Run with:

```sh
python3 -m unittest discover -s tests/host -v
```

**Black box is the whole point.** Each test runs the script as a subprocess,
by its path, and asserts only on what a caller can observe: stdout, stderr, and
exit status. Never import, source, or grep a script's text. The same tests must
pass unmodified after the script is rewritten in another language.

**No containers, no network, seconds to run.** Give each test a temporary
directory at the front of `PATH` holding fake executables (`docker`, `podman`,
`podman-compose`, `docker-compose`, `powershell.exe`, `wslview`, `explorer.exe`,
`xdg-open`, `open`, `uname`, `curl`, `shellcheck` as needed). A fake records its
argv to a file and returns a canned stdout and exit status. Write the fakes as
small `#!/usr/bin/env python3` scripts generated by a shared helper in
`tests/host/fakes.py`. Build the rest of `PATH` from only what the script under
test legitimately needs, so a real `docker` or `podman` on the machine can never
leak into a test.

Pin at least these behaviours. Read each script first and add any observable
behaviour this list misses.

- **`compose-command`**
  - The search order: `docker compose`, then `podman compose`, then
    `podman-compose`, then `docker-compose`, each skipped when its version probe
    fails.
  - A `docker` binary whose `compose version` fails (Docker Desktop with WSL
    integration off) is skipped, not selected.
  - The four output modes for one detected engine: default, `--engine`,
    `--make`, `--explain`.
  - Nothing found: exit 1; `--explain` names what is missing for docker and for
    podman separately; the default mode writes its one-line hint to stderr.
- **`compose-up`** (env `COMPOSE`, `ENGINE`)
  - Running container's image id differs from the current image id: prints the
    Kept/Lost explanation and runs `up -d --force-recreate`.
  - Ids equal: plain `up -d`, no explanation.
  - Ids equal except for a `sha256:` prefix on one side: treated as equal.
  - No existing container, and no image yet: plain `up -d`.
  - The image found only under the `localhost/` name (Podman).
  - The echoed `+ … up -d` line; a two-word `COMPOSE` such as `docker compose`.
  - `COMPOSE` or `ENGINE` unset: non-zero exit and a message.
- **`run-quiet`**
  - Exit status of the wrapped command is preserved (0, 1, 7).
  - Each of the two filtered patterns is dropped from stderr; any other stderr
    line passes through; stdout is untouched.
  - A filtered line on **stdout** is not dropped: the filter is stderr-only.
  - `VERBOSE=1` disables filtering entirely.
- **`open-url`**
  - The URL is always the first line of stdout, on every path.
  - `BROWSER` set to an available command wins; `BROWSER` naming a missing
    command is ignored.
  - WSL (simulate with `WSL_DISTRO_NAME=Ubuntu`): `wslview`, then
    `powershell.exe`, then `explorer.exe`; `explorer.exe` exiting non-zero still
    yields exit 0; no opener at all yields exit 0 with the fallback message;
    `xdg-open` is **never** called on WSL even when present.
  - macOS (fake `uname` printing `Darwin`): `open` is used.
  - Linux (fake `uname` printing `Linux`): `xdg-open` is used; with none, exit
    0 and the fallback message.
  - The non-WSL cases cannot run on a WSL host, because the script also reads
    `/proc/version`. Skip them there with `unittest.skipIf` and a reason. They
    will run in CI, which is real Linux.
- **`check-host`**
  - Engine found: exit 0, reports compose command and engine, prints "Ready".
  - Podman with major version below 4: the warning and the requirements-file
    hint.
  - No engine: exit 1, and the explanation from `compose-command --explain`.
  - Resource lines are present; assert their shape, not the machine's numbers.
- **`base-image-digest`** (fake `curl`)
  - Token then digest: prints the digest, exit 0; the distro argument reaches
    the manifest URL (`…/manifests/<distro>-ros-base`), default `lyrical`.
  - No token in the response: non-zero exit and a message.
  - No digest header: non-zero exit and a message.
  - The header match is case-insensitive, and a trailing `\r` is stripped.

**Prove the tests have teeth.** For each of the six scripts, make one temporary
mutation that breaks a pinned behaviour (swap the search order; drop the exit
status; remove a filter pattern), show at least one test failing, then revert
the mutation. Confirm with `git status` that no mutation remains. Record each
mutation and the failing test in the report. A test that cannot fail is not a
test.

### 2. `make check`

A new target, authorized here (guardrail 5 otherwise says STOP AND ASK):

```make
check:
	python3 -m unittest discover -s tests/host
```

It needs no engine, so it must not depend on `require-engine`. Add it to
`.PHONY`, and to `make help` under "Working on this project", above `make lint`:
"Fast tests for the host scripts (seconds, no containers)". Add the matching row
to the README's commands table.

### 3. CI

In the `lint` job only, after the lint step, add a step that runs
`python -m unittest discover -s tests/host -v`. That job already sets up Python
3.9, so this also proves the tests are 3.9-compatible.

### 4. Container-script coverage in `scripts/smoke-container`

The executor contract says never modify an existing test file. This prompt
overrides that for this one file, **additively only**: insert one new `step`,
`'Container helpers: tutorial, init-workspace, pkg refusals'`, immediately before
the `'Persistence across container recreation'` step. Every existing line stays
byte-identical. Use the existing helpers and style (`step`, `ok`, `bad`, `check`,
`in_desktop`), mind `set -e` when a command is expected to fail, and stay
engine-agnostic.

Add checks for:

- `init-workspace` twice in a row: the second run says the workspace is already
  initialized, and the marker file's checksum is unchanged.
- `tutorial` with no arguments: exit 2 and usage text.
- `tutorial clone` from a local repository (create a small git repository with
  one commit under `/tmp` inside the container; no network): the clone lands in
  `/workspace/src`, and the echoed `+ git …` line is present.
- `tutorial list` names the cloned repository.
- `tutorial build` with a package name echoes `+ colcon build --symlink-install
  --packages-select <name>` and succeeds. Reuse a package an earlier step
  already created.
- `pkg` with no arguments: exit 2 and usage text.
- `pkg new <name> --python --interfaces`: exit 1, and the message that interface
  packages must be ament_cmake.
- `pkg new` on a package that already exists: non-zero exit, and a file inside
  the existing package is byte-identical afterwards. This pins guardrail 7. If
  the current behaviour is *not* a refusal, that is a finding: record exactly
  what happens under Deviations and pin what is true today. Do not change `pkg`.

## Ground rules

- **No script changes.** Nothing under `scripts/` or `docker/` changes, except
  the additive step in `scripts/smoke-container` and the temporary, reverted
  mutations.
- The tests pin what the scripts do **today**. If a script's behaviour looks
  wrong, pin it anyway and raise it under Open questions. Fixing it here would
  break the rule that tests and code never change in the same stage.
- Assert on exact text where the docs, the suite, or another script depend on
  it (the `+ …` echo lines, `--make` output, the digest). Elsewhere assert on
  the key phrase, not the whole paragraph.
- Tests must not write outside their temporary directories, and must not
  require docker, podman, or network access.

## Allowed files

- `tests/host/**` (new)
- `Makefile` — the `check` target, its `.PHONY` entry, and its `make help` line
- `.github/workflows/docker-image.yml` — one new step in the `lint` job
- `README.md` — one new row in the commands table
- `scripts/smoke-container` — the one additive step described above
- `docs/stages/stage-02-REPORT.md` (new)

Anything else is out of scope. Needing another file is a Blocked finding.

## Definition of Done

- Baseline on the unmodified base: `make lint` and `make selftest` (32/32
  expected), recorded before any change.
- `make check` passes, in under 30 seconds, with the skipped tests listed and
  explained.
- `make check` also passes with `PATH` stripped of any real `docker` and
  `podman`, proving the fakes are the only engines the tests see.
- `make lint` passes.
- `make selftest` passes with every baseline check still present and passing,
  plus the new step's checks. Report the new total.
- One recorded, reverted mutation per host script, each caught by a test.
- `git diff python-port --stat` shows only allowed files, and
  `git diff python-port -- scripts/smoke-container` shows insertions only.

## Commit

One commit, containing the change and `docs/stages/stage-02-REPORT.md`, with
exactly this message:

```
test: pin the behaviour of every script before porting it
```

Then attempt `git push -u origin stage-02-tests-before-ports`. Do not push to
`python-port` or `main`.

## Report requirements

`docs/stages/stage-02-REPORT.md` must contain:

1. A checklist echo of "The change" and the Definition of Done.
2. Baseline and final gate outputs, verbatim and side by side.
3. The `make check` output, with test counts per script and every skip reason.
4. The six mutations: what was changed, which test failed, proof of the revert.
5. For each host script, any observable behaviour you found that this prompt's
   list missed, and whether you pinned it.
6. What `pkg new` does today on an existing package, verbatim.
7. `git diff python-port --stat`.
8. **Deviations**, numbered and honest, including the boring ones.
9. **Open questions**, including any behaviour you pinned but believe is wrong.

## Blocked protocol

STOP and commit only the report, with a BLOCKED section giving the exact
failing output and why each permitted path is closed, if:

- a gate already fails on the unmodified base;
- a listed behaviour cannot be observed from outside the script without
  changing the script (say which, and what seam would be needed);
- the change cannot be made inside the allowed files;
- any guardrail in `docs/stages/README.md` says STOP AND ASK.

A clean block is a successful execution.
